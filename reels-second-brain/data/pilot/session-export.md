# 세션 기록: "4주 뒤에도 쓰는" 노션 가계부 (Phase 0 → Phase 1 시범)

- 기간: 2026-10-24 ~ 2026-10-25
- 작업 브랜치: `claude/notion-budget-app-design-qk86cw` (본 기록과 데이터는 `claude/pilot-data-export`)
- 정리 방식: 대화 전체를 시간순으로 요약했습니다. 개인정보, 토큰, API 키는 넣지 않았습니다.
- 진행 규칙: 판단이 필요한 지점은 임의로 진행하지 않고 사용자에게 질문한 뒤 멈춥니다. 각 Phase 끝에 결과물, 근거 링크, 결정 질문을 보고하고 승인 후 다음 단계로 넘어갑니다.

## 0. 사용자의 요청

가계부를 시작하기 어렵거나 귀찮아하는 사람이 4주 뒤에도 쓰는 노션 가계부를 만든다. 기능 수가 아니라 아래 세 가지로 평가한다.

1. 입력 부담 최소화
2. 숫자 신뢰도(실제 잔액과 일치)
3. 매주 1개의 행동 가능한 인사이트

| Phase | 내용 |
|---|---|
| 0 | 은행·카드 연동 선택지, 투자 기능의 법적 검토, Notion API 제약 확인 |
| 1 | 앱 리뷰·댓글 원문 수집 → 분류 기준표 → LLM 분류와 kappa 검증 → Kano·ODI → JTBD 질문지 |
| 2 | 데이터 모델 설계 |
| 3 | 구현 (파서, 분류, 이체 매칭, Notion 기록, 예측 기준선) |
| 검증 | 월 합계 = 카드사 청구액·통장 잔액 (원 단위 일치) 등 |

## 1. Phase 0 — 실현 가능성·규제 게이트

### 1-1. 조사 과정과 한계
- 처음에는 `law.go.kr`가 네트워크 정책에 막혀 법령 원문을 직접 볼 수 없었습니다. 웹 검색 발췌로 교차 확인하고 확인 수준(공식 / 2차 출처 / 미확인)을 표시한 v1 보고서를 냈습니다.
- 사용자가 도메인을 허용한 뒤 국가법령정보센터 오픈 API로 현행 조문을 받아 v1의 미확인 항목을 원문과 대조해 v2로 고쳤습니다.
- 대조한 법령 판본: 신용정보법(2026-09-11 시행), 시행령(2026-09-11), 신용정보업감독규정(2026-10-23 발령), 전자금융거래법(2026-10-02 시행), 자본시장법(2026-10-02 시행), 같은 법 시행령(2026-10-13).

### 1-2. 데이터 연동 선택지 판정

| 선택지 | 판정 | 핵심 이유 |
|---|---|---|
| 금융 마이데이터 API | 탈락 | 개인이 직접 쓸 표준 채널 없음. 허가 사업자만 가능 |
| 오픈뱅킹 | 탈락 | 이용기관은 금융결제원과 계약한 핀테크 사업자·은행 |
| 상용 스크래핑 API | 탈락 | 이체 가능한 자격증명을 외부에 맡김. 은행 약관이 접근매체 대여·위임을 금지하고 사고 책임을 이용자에게 지울 수 있음 |
| 엑셀/CSV 내보내기 | **주 경로** | 자격증명 보관 위험 없음. 기관 원본이라 대사 기준으로 적합 |
| 결제 알림 문자·푸시 파싱 | **보조 경로** | 실시간 감지용. 정산·대사에는 쓰지 않음 |

### 1-3. 원문 대조로 정정한 사항 (v1 → v2)
- 전자금융거래법 제6조 ③의 접근매체 "보관·전달" 금지는 대가 수수 또는 범죄 목적이 있을 때만 적용됩니다. 처벌은 제49조 ④, 5년 이하 징역 또는 3천만 원 이하 벌금입니다. (v1에서는 출처마다 형량이 달라 충돌했습니다.)
- 투자자문 대상에는 부동산, 부동산 관련 권리, 금융기관 예치금이 포함됩니다 (자본시장법 시행령 제6조의2).
- 계좌 거래내역은 법적으로 "본인"에게도 전송을 요구할 수 있습니다 (신용정보법 시행령 제28조의3 ⑥). 다만 개인이 이 권리를 쓸 표준 채널은 찾지 못했습니다.

### 1-4. 판매 계획에 따른 법적 검토 (사용자가 추후 크몽·SNS 판매를 밝힌 뒤 추가)
- **신용정보법:** 판매자가 구매자 데이터에 접근하는지가 핵심입니다. 신용정보업감독규정 제3조의3 ①1호는 "인터페이스만 제공하고 사업자에게 접근·조회·관리 권한이 없는 경우"를 본인신용정보관리업에서 제외합니다.
  - 구매자 PC에서 실행하고 구매자 소유 Notion에 기록하는 구조는 허가가 필요 없을 가능성이 높습니다.
  - 판매자 서버가 데이터를 처리하는 SaaS는 허가 쟁점이 생깁니다.
- **자본시장법:** 투자자문업의 핵심 요건은 "영업으로"입니다. 판매를 전제로 한 규칙 기반 리밸런싱 알림(I3)에는 다섯 가지 가드레일이 필요합니다.
  1. 목표 비중 프리셋을 제공하지 않습니다.
  2. 종목·상품명을 제시하지 않습니다.
  3. 고객 응대는 사용법 안내로 한정합니다.
  4. 자동매매·주문 연동은 하지 않습니다.
  5. 수익이나 성과 표현을 쓰지 않습니다.

### 1-5. Notion API 제약과 구조 판단
- 호출 한도는 연결당 평균 초당 3회입니다. 2025-09-03 버전부터 database와 data source가 분리됐습니다.
- 페이지 응답에서 relation은 25개까지만 반환되고, 이를 참조하는 formula도 25개만 계산됩니다. 월 거래가 수백 건이라 Notion rollup 값은 계산 근거로 쓸 수 없습니다.
- **판단:** "노션 = 화면, 계산 = 외부 Python" 구조가 맞습니다.
- 한계: `developers.notion.com`은 세션 내내 차단되어 검색 발췌로 확인했습니다.

### 2-3. 표본 130건을 읽고 얻은 신호 (정량 확인 전)
- 문자 자동입력 가계부(네이버 가계부·똑똑가계부·편한가계부)는 카드사가 알림을 앱 푸시나 카카오 알림톡으로 바꾸거나 문구를 바꾸면 인식이 끊깁니다. 사용자는 결국 수기 입력으로 돌아갑니다.
- 이 때문에 알림 해석 규칙을 휴대폰 안에 넣지 않고 PC 쪽 해석기 하나로 모으기로 했습니다.
- 은행 앱 리뷰의 대부분은 로그인·인증·송금 이야기라 키워드 오탐 규칙을 기준표에 추가했습니다 (이체·문자·포인트·알림·연결).
- 이것은 표본 인상일 뿐이며, 전체 분류 결과로 검증해야 합니다.

### 2-4. 중단된 항목과 사유

| 항목 | 상태 | 사유 |
|---|---|---|
| LLM 시범 분류 (Haiku 5.5, 200건) | **미실행** | 세션에 `ANTHROPIC_API_KEY`가 없음. 환경 시크릿은 새 세션부터 적용됨 |
| 독립 재분류 100건 + Cohen's kappa | 미실행 | 위와 동일. 다른 모델로 하기로 함 (Codex는 이 환경에 없음) |
| Kano 분류, ODI 기회 점수, 상위 5개 문제 | 미실행 | 분류 결과 필요 |
| 네이버 블로그 수집 | 보류 | 키 미제공. 본문 수집은 하지 않기로 함 |
| 원본 Google Drive 보관 | 미실행 | Drive 폴더 생성이 세션의 권한 검사에서 차단됨. 압축 파일을 사용자에게 전달해 직접 보관하도록 함 |

- **네이버 블로그 본문 수집을 제거한 이유:** `blog.naver.com` robots.txt가 AI 학습·RAG 목적의 봇 접근을 명시적으로 금지합니다. 받은 텍스트를 LLM으로 분류하는 이 작업은 그 취지에 해당하므로, 공식 검색 API가 주는 요약만 쓰기로 했습니다.
- 분류 모델: 사용자가 Haiku 5.5로 200건 시범을 먼저 돌리기로 결정했습니다. 전체 진행 여부는 시범의 비용과 품질을 보고 정합니다.
- 예상 비용(실측 아님): 전체 21,948건 Haiku 5.5 Batch 기준 약 $3~8.

## 3. 아직 답을 받지 못한 질문
- **Phase 0 Q4 대사 방법:** 하나은행 거래내역 엑셀(잔액 열, 파일 암호 여부), 3개 카드사의 이용내역과 결제일 기준 청구 명세서를 엑셀로 받을 수 있는지는 Phase 2 샘플로 확인합니다.

## 4. 다음 단계
1. 환경 시크릿에 `ANTHROPIC_API_KEY` 등록 후 새 세션 시작 (네이버 키는 선택).
2. 리뷰 재수집 (약 15분) → Haiku 5.5 200건 시범 → 비용·품질 보고 → 전체 분류 → 다른 모델로 100건 재분류와 kappa(0.7 이상) → Kano·ODI → 상위 5개 문제.
3. 상위 5개 문제를 근거 리뷰 원문 링크와 함께 보고하고 Phase 1 종료.
4. Phase 2 승인 후 샘플 파일로 데이터 모델 설계.
