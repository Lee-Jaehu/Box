# 화면 안 보고 기록하기: 설계서 (2026-11-19)

목표는 버튼을 예쁘게 만드는 게 아니라, **아기를 안은 채 잠금 해제 없이, 화면을 보지 않고 기록하는 것**입니다.
아내는 Claude 계정이 없으므로, 기록을 받는 곳을 Claude 밖(구글 시트 + Apps Script)으로 옮깁니다.

## 0. 받은 원자료와 그 영향

| 원자료 | 내용 | 설계에 미친 영향 |
|---|---|---|
| 기종 | 아빠 아이폰 17, 엄마 아이폰 18 Pro | 둘 다 액션 버튼이 있는 세대 (애플 문서: iPhone 15 Pro 이후 지원 기종). 두 폰 모두 최신 iOS라 잠금화면 단축어 컨트롤(iOS 18.2+) 사용 가능 |
| 애플워치·에어팟 | 있음 | 에어팟 + 시리 = 손·눈 모두 0. 워치 = 폰이 멀리 있을 때의 예비 경로 |
| 맥 | 없음 | **네이티브 앱(SwiftUI·Xcode) 불가.** 1단계를 단축어로만 설계 |
| 개발자 계정 | 만들지 않음 | **TestFlight·라이브 액티비티 불가.** 3장에 대체안 |
| 새벽 수유 관찰 메모 | 아직 없음 | 1장 표의 우선순위는 가정입니다. 메모를 받으면 바꿉니다 |
| 아내가 가장 자주 기록할 3가지 | 아직 없음 | 지금은 수유 시작·끝, 기저귀, 젖병으로 가정 |
| 기존 기록의 '누른 시각 vs 사건 시각' | 비교 불가 | 지금 앱은 누른 시각만 저장해서 지연을 잴 수 없습니다. 5장에서 다른 방법으로 잽니다 |
| 구글 드라이브 | **용량 초과** | 이 계정으로는 시트를 만들 수 없음. 공간 정리 또는 육아 전용 계정 필요 (README 0단계) |

## 1. 기록 동작별 조작 경로

표의 칸 설명
- **터치**: 0 = 말만 하면 됨, '갖다 댐' = NFC 스티커에 폰을 대기
- **화면**: 결과를 시리가 소리로 알려 주므로 모든 경로에서 화면을 보지 않아도 됩니다. 단, 잠금화면 버튼은 누를 위치를 한 번 봐야 합니다.
- **잠금 해제**: 애플 문서에는 '잠겨 있을 때 실행 허용' 설정만 있고, 잠긴 상태에서 실제로 끝까지 실행되는지는 단정하지 않습니다. 그래서 전부 **"README 5단계 기기 시험으로 확인"**으로 둡니다.

| 기록 | 엄마 1순위 | 엄마 2순위 (예비) | 아빠 1순위 | 터치 | 요구 조건 |
|---|---|---|---|---|---|
| 수유 시작·끝 (평소 종류) | **액션 버튼 한 번**: 진행 중이면 끝, 아니면 시작 (방향은 지난번 반대쪽 자동) | 뒷면 두 번 톡톡 = "수유 끝" | 대신 시작은 웹 화면 | 1 (버튼) | 액션 버튼 기종, 단축어 |
| 왼쪽/오른쪽 직수 시작 | 에어팟으로 "시리야, 왼쪽 직수" | 워치 시리 | — | 0 | 시리, 단축어 이름 = 말할 문장 |
| 직수 + 유축 시작 | "시리야, 직수 유축" | 유축기 NFC 스티커 | — | 0 | 같음 |
| 유축만 시작·끝 | **유축기 NFC 스티커** (한 번 대면 시작, 다시 대면 끝) | "시리야, 유축 시작" / "수유 끝" | — | 갖다 댐 | NFC 지원 아이폰(XS 이후), 스티커 |
| 수유 끝 | 액션 버튼 또는 뒷면 두 번 톡톡 | "시리야, 수유 끝" | — | 1 / 0 | 뒷면 탭: iPhone 8 이후 |
| 기저귀 소변 / 대변 / 둘 다 | "시리야, 기저귀 소변" | 뒷면 세 번 톡톡 = 소변 | **기저귀대 NFC 스티커 2개** (소변·대변) | 0 / 갖다 댐 | |
| 젖병 (종류·양) | — | — | "시리야, 젖병 기록" → 시리가 "모유? 분유?", "몇 밀리?"를 물음 | 0 | |
| 수면 시작·끝 (선택) | "시리야, 아기 잠" (한 번 = 잠듦, 다시 = 깸) | — | 같음 | 0 | 4장 '졸림' 추정에만 쓰임. 안 쓰면 생략 |
| 울음 | 자동: 사운드 인식 '아기 울음' → 단축어 자동 실행 | "시리야, 아기 울어" | 같음 | 0 | 사운드 인식 켜기 |
| 울음 그침 (무엇으로) | "시리야, 울음 그침" → "먹임·기저귀·재움·안아줌·모름" 중 대답 | — | 같음 | 0 | |
| 지금 상황 듣기 | "시리야, 수유 상황" → "마지막 수유 2시간 10분 전, 다음은 오른쪽" | 잠금화면 컨트롤 | 같음 | 0 | |
| 잘못 기록함 | "시리야, 방금 취소" (15분 안의 내 마지막 기록) | 웹 화면 기록 탭 | 같음 | 0 | |
| 잠금화면 버튼 | '수유 버튼'·'기저귀 소변' 두 개 | — | '기저귀 소변'·'수유 상황' | 1 | iOS 18.2+ 잠금화면 컨트롤 |

라이브 액티비티(잠금화면 타이머)는 네이티브 앱만 만들 수 있어서 이번 조건에서는 제외했습니다. 대신 "수유 상황"을 물으면 진행 시간을 말해 줍니다.

**근거 (애플 문서)**
- [Run shortcuts with the Action button](https://support.apple.com/guide/shortcuts/run-shortcuts-with-the-action-button-apdfea15680b/ios): 설정 > 액션 버튼 > 단축어. 지원 기종은 iPhone 15 Pro 이후.
- [Run shortcuts by tapping the back of your iPhone](https://support.apple.com/guide/shortcuts/run-shortcuts-tapping-iphone-apd897693606/ios), [Use Back Tap](https://support.apple.com/en-us/111772): 설정 > 손쉬운 사용 > 터치 > 뒷면 탭, iPhone 8 이후.
- [Use Siri to run shortcuts](https://support.apple.com/guide/shortcuts/run-shortcuts-with-siri-apd07c25bb38/ios): 단축어 이름을 말하면 실행. 기본 시리 명령과 이름이 같으면 단축어가 우선.
- [Run shortcuts from Apple Watch](https://support.apple.com/guide/shortcuts/run-shortcuts-from-apple-watch-apd5888b0858/ios): 'Apple Watch에서 보기'를 켠 단축어만. 워치가 잠겨 있으면 앱을 여는 단축어는 잠금 해제를 요구.
- [What's new in Shortcuts for iOS 18](https://support.apple.com/en-us/121131): iOS 18.2부터 단축어를 제어 센터·잠금화면 컨트롤로.
- [Add automations](https://support.apple.com/guide/shortcuts/add-automations-apdfbdbd7123/ios), [Event triggers](https://support.apple.com/en-ca/guide/shortcuts/apd932ff833f/ios): NFC·사운드 인식은 확인 없이 자동 실행 가능한 자동화이고, '잠겨 있을 때 실행 허용' 설정이 있음.
- [Share shortcuts](https://support.apple.com/guide/shortcuts/share-shortcuts-apdf01f8c054/ios), [Import questions](https://support.apple.com/guide/shortcuts/add-import-questions-to-shared-shortcuts-apdf330fd3a0/ios): iCloud 링크로 공유하고, 받는 사람이 자기 값(엄마/아빠, 주소)을 입력.

## 2. 1단계 구조 (이번 주, 앱 설치 없음)

```
[에어팟·시리 / 액션 버튼 / 뒷면 탭 / NFC / 워치 / 잠금화면]
        │  단축어: "URL의 콘텐츠 가져오기"  (…/exec?k=토큰&by=mom&a=동작)
        ▼
[구글 Apps Script 웹 앱]  ── 기록하고 시리가 읽을 한 문장을 돌려줌 ("왼쪽 직수 시작했어요")
        │
        ▼
[구글 시트: events · bags · config 탭]  ← 사람이 표로도 볼 수 있음
        ▲
[웹 페이지 …/exec?k=토큰]  ← 지금 앱 화면 그대로. 엄마·아빠 모두 Claude 없이 사파리로 열고 홈 화면에 추가
```

**저장소로 구글 시트 + Apps Script를 고른 이유** (Firebase와 비교)
- 단축어는 서버 쪽 판단이 필요합니다. 진행 중이면 끝내기, 방향 자동 선택, 방금 취소, 울음 원인 순위 같은 것들입니다.
  - Apps Script는 이 판단을 무료로 서버에서 돌립니다.
  - Firebase는 무료 요금제에서 서버 함수를 쓸 수 없어서, 이 판단을 전부 단축어 안에 넣어야 합니다.
- 기록이 시트에 남아서, 앱이 멈춰도 두 분이 표로 바로 보고 고칠 수 있습니다.
- 기존 지침대로 동시 수정도 막습니다: 서버 잠금(LockService) + 팩마다 version 번호.

**만든 것**
- `stage1/gas/Code.gs`: 서버
  - 단축어 동작 12종: 토글, 시작, 끝, 기저귀, 젖병, 울음, 그침, 잠, 상황, 취소 등
  - 웹 페이지용 함수
- `stage1/gas/Index.html`: 지금 앱 화면에 저장 방식만 Apps Script로 바꾼 것 (`app/build.js`가 생성)
- `stage1/gas/Migrate.gs`: 아티팩트 기록 13건과 설정 옮기기
- `stage1/README.md`: 설치 순서, 단축어 목록, 기기 시험표
- 테스트
  - `tests/gas.test.js`: 서버 동작 13개 (흉내 낸 구글 환경)
  - `tests/gas-web.check.js`: 웹 페이지와 서버를 한 브라우저에서 연결해, 단축어 기록 → 화면 반영 → 젖병 팩 차감까지 확인

## 3. 2단계 (네이티브 앱): 지금 조건으로는 불가

SwiftUI, App Intents, WidgetKit 컨트롤, ActivityKit(라이브 액티비티), CloudKit 공유로 가려면 **맥(Xcode)**과 **애플 개발자 계정(연 99달러, TestFlight 배포)**이 둘 다 필요합니다. 두 분 조건에서는 둘 다 없어서 이 단계는 설계만 남깁니다.

- **2단계가 더해 주는 것**
  - 잠금화면·다이내믹 아일랜드의 수유 타이머와 '끝' 버튼 (라이브 액티비티)
  - 인터넷이 끊겨도 폰에 먼저 저장했다가 나중에 보내기
  - 시리 응답 속도 개선 (구글 서버 왕복 1~3초가 없어짐)
  - 서버 없이 iCloud로 부부 공유
- **구조**
  - App Intents 하나로 시리, 액션 버튼, 잠금화면 컨트롤, 위젯을 함께 처리
  - SwiftData로 폰 안에 저장하고 CloudKit 공유 영역으로 부부 계정 동기화
  - ActivityKit으로 진행 중 수유 타이머
  - TestFlight 내부 테스터 2명으로 설치
- **2단계로 넘어갈 기준** (셋 다 충족할 때)
  1. 2주 동안 단축어 경로가 전체 기록의 70% 이상 (단축어 방식이 생활에 붙었다는 뜻)
  2. 그런데도 "응답 대기·인터넷 실패로 기록 못 함"이 10건 중 1건 이상이거나, "진행 시간을 보려고 폰을 켠 일"이 하루 3번 이상
  3. 맥과 개발자 계정을 구할 수 있음

1, 2가 충족되는데 3이 안 되면, 무료 앱 **Scriptable**로 잠금화면 위젯("마지막 수유 2:10 전 · 다음 오른쪽")만 따로 붙이는 방법을 검토합니다. 이번 범위에는 넣지 않았습니다.

## 4. 울음

**(a) 아이폰 기본 울음 감지를 기록과 연결**
1. 설정 > 손쉬운 사용 > 사운드 인식에서 '아기 울음'을 켭니다.
2. 단축어 > 자동화 > 사운드 인식 > 아기 울음 → '아기 울어' 단축어를 연결하고, 즉시 실행을 켭니다.
3. 서버가 울음을 기록하고 가능성 순위를 시리로 말합니다.
4. 두 폰이 같은 울음을 들으면 5분 안의 울음은 하나로 기록합니다.

사운드 인식은 위급한 상황에 의존하지 말라는 애플의 안내가 있습니다. 이 기능은 기록과 참고용이고, 안전 장치가 아닙니다. 사운드 인식 목록에 '아기 울음'이 있는지는 기기에서 확인합니다 (README 5단계).

**(b) 내 기록으로 보는 원인 가능성 순위** (분류 모델이 아닙니다)

| 원인 | 점수 | 근거 |
|---|---|---|
| 배고픔 | 마지막 수유 후 시간 ÷ **최근 24시간 수유 간격의 중앙값** (기록 없으면 150분) | 신생아는 하루 8~12회, 2~3시간 간격으로 먹음 (AAP). 울음은 배고픔의 늦은 신호이고, 입 찾기·손 빨기가 먼저 옴 (AAP HealthyChildren) |
| 졸림 | 깨어 있은 시간 ÷ **우리 아기의 깨어 있는 시간 중앙값** (잠 기록 5회 미만이면 60분) | 60분은 근거가 약한 가정값이라 기록이 쌓이면 아기 자신의 값으로 바꿈. 잠을 기록하지 않으면 이 항목은 빠짐 |
| 기저귀 | 마지막 교체 후 시간 ÷ 180분, 그 뒤 수유가 있었으면 +0.3 | 신생아는 수유 직후 변을 보는 경우가 많음 |

시리는 상위 2개를 이유와 함께 말합니다. 예: "배고플 수 있어요. 마지막 수유 2시간 50분 전. 다음은 기저귀일 수 있어요…"

**(c) 무엇으로 그쳤는지:** "시리야, 울음 그침" → 먹임/기저귀/재움/안아줌/모름. 이 기록이 순위가 맞았는지 확인하는 정답이 됩니다.

**얼굴 사진으로 원인·통증을 판단하는 기능을 넣지 않는 이유**
- 신생아 통증을 얼굴로 평가하는 척도(NFCS, Grunau & Craig 1987; NIPS, Lawrence 외 1993)는 훈련받은 의료진이 관찰하는 도구입니다.
- 이를 자동화한 연구들(COPE 영상 데이터, Brahnam 외 2006 등)은 소수의 NICU 신생아로 만든 연구용 결과이고, 집에서 폰 카메라로 쓰도록 검증된 적이 없습니다.
- 울음으로 원인을 맞히는 공개 데이터(Donate-a-Cry 등)도 수백 개 녹음에 부모가 짐작으로 붙인 라벨이라, 정답 자체가 불확실합니다.
- 아들은 장 수술 후 회복 중이라, 앱이 "괜찮아 보여요"라고 잘못 안심시키는 위험이 놓치는 위험보다 큽니다.
- 그래서 "아픈지"는 기존 위험 신호 기준표(설계서 4장)와 의료진 연락으로만 판단합니다.
- 인용한 연구의 서지는 원문 대조가 필요합니다.

## 5. 검증 계획 (설치 후 2주)

| 무엇을 | 어떻게 재나 | 유지 기준 | 아니면 |
|---|---|---|---|
