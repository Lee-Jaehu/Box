# 팀 요약 페이지 + 팀 주간보고 묶음 PPT

> 2026-10-06. 템플릿 `주간업무PPT_Template_v2.pptx`의 0번(요약 양식)과 1번(실제 작성본)을 기준으로 만들었다.
> 예시: `demo/team/out/` (미리보기 `demo/team/out/preview/*.png`)

## 1. 양식 해석

| 템플릿 장 | 역할 | 코드가 찾는 방법 |
|---|---|---|
| 0번 | 팀 요약 양식: 제목 `1. TF 담당 (1/1)`, 작성자, 업데이트 시간, 본문 `pjt_header` 한 칸 | 도형 `slide_title·author·updated_at·pjt_header`가 있고 `main_table`이 없는 첫 장 |
| 1번 | 실제 작성본 참고 (자동보정선행개발팀) | 출력하지 않음 |
| 2번 | 과제별 주간 장표 양식 | 필수 도형(`main_table` 등)이 있는 첫 장 |
| 3번 | 주간 장표 작성 예시 | 출력하지 않음 |

0번 안내문의 요구사항
- 과제마다 배경/목적, 진행 현황, 이슈·잘한점, 향후 계획을 넣는다.
- 기존 내용은 검정색으로 쓰고, 길면 요약한다. 신규 내용은 파란색으로 쓴다.
- 이슈·잘한점은 다른 카테고리보다 자세히 쓴다.

1번 작성본의 표시 형식 (그대로 따른다, 카테고리 이름은 표시하지 않음)
```
1. 과제명                                     ← 굵게
- 경어체 완결 문장입니다.(10/2)                 ← 신규면 파랑 1414FE, 기존이면 검정
  . 세부 내용                                  ← 원인·영향·대응, 성과 수치
- ...
(빈 줄)
2. 과제명
```
- 글자 크기는 11pt이고, 넘친 과제는 10.5pt로 줄인다.
- 날짜는 마침표 바로 뒤에 `(M/D)`로 붙인다.

## 2. 흐름 (AI는 문장만, 나머지는 Rule)

```
팀 과제 목록(org.team) ─┬─ weekly/cumulative (없으면 주간 정리 먼저 실행)
                        ├─ project_summary  ← EXAONE: 과제 1건 요약 JSON (과제당 줄 수 한도 포함)
                        │     └ Rule: 순서 정렬 · 신규(파랑) 판정 · 수치/날짜/근거 검증 · 문체 검사 → 저장
                        └─ 주간 장표 내용 (기존 pptgen과 같은 코드)
→ 요약 페이지 배치(Rule): 11pt → 10.5 → 10pt, 그래도 넘치면 과제 단위로 다음 장 "(1/2)"
→ 한 파일: [요약 n장] + [과제 1 주간 장표] + [과제 2 주간 장표] ...
→ 재검사 보고서 {파일명}_check.txt
```

| 단계 | 담당 | 결과 |
|---|---|---|
| 카테고리별 문장 작성, 기존 내용 합치기, 이슈·잘한점 세부 | EXAONE (`prompts/project_summary.*.txt`) | `data/derived/summary/{과제}/{주차}.json` |
| 카테고리 순서(배경 → 진행 → 이슈·잘한점 → 계획) | Rule | 같은 파일 |
| 파랑/검정: `source_ids`에 이번 주 기록 ID가 있으면 파랑. 배경은 항상 검정 | Rule | `new` 필드 |
| 수치·날짜·근거 ID 검증, 경어체·길이·날짜 표시 검사 | Rule | `output/{과제}/summary_check_{주차}.txt` |
| 줄 수 계산, 글자 크기, 페이지 나누기, 색·글꼴 재검사 | Rule | PPT + `_check.txt` |

의미 검증에 실패한 문장도 주간 정리처럼 **저장하고 보고서에 표시**한다(시연에서 보여 주기 위함). 구조(스키마)가 틀리면 저장하지 않는다.

## 3. 요약 JSON 형식 (`schemas/project_summary.schema.json`)

```json
{
  "project_id": "P-ASM-001", "week": "2026-W40", "project_name": "ESWA 재료교체 불량 개선", "max_lines": 12,
  "week_source_ids": ["D-260928-ljh-01", "..."],
  "items": [
    {"category": "background", "text": "재료교체 구간 Y축 불량(...)을 개선하는 과제입니다.", "source_ids": ["P-ASM-001"], "new": false, "details": []},
    {"category": "progress", "text": "1·2차 로직 적용으로 ... 감소했습니다.(8/13~9/4)", "source_ids": ["P-ASM-001"], "new": false, "details": []},
    {"category": "good", "text": "추석 이후 2주 데이터에서도 ... 더 감소했습니다.(9/28)", "source_ids": ["D-260928-ljh-01"], "new": true,
     "details": [{"text": "ESWA MEB E77 0.171% → 0.139%, ...", "source_ids": ["D-260928-ljh-01"], "new": true}]},
    {"category": "issue", "text": "북미 현지 PLC 펌웨어 버전이 ... 필요합니다.(10/1)", "source_ids": ["D-261001-ljh-01"], "new": true, "details": ["..."]},
    {"category": "plan", "text": "... 적용할 예정입니다.(~10/13)", "source_ids": ["D-261001-ljh-01"], "new": true, "details": []}
  ],
  "ai": {"model": "...", "prompt_id": "project_summary", "prompt_version": "v0.7", "input_hash": "..."}
}
```
- EXAONE 응답에는 `category·text·source_ids·details`만 있다. `new`, 순서, meta는 코드가 채운다.
- live 모드에서는 프롬프트 입력이 지난번과 같으면(`input_hash`) 다시 호출하지 않고 저장된 요약을 쓴다.

## 4. 분량 규칙

| 항목 | 값 | 근거 |
|---|---|---|
| 본문 영역 | `pjt_header` 위쪽(0.94in) ~ 7.10in(쪽번호 위), 폭 10.56in | 템플릿 0번 |
| 한 줄 높이 | 글자 크기 × 1.17 (LG스마트체 실측, 주간 장표와 같음) | |
| 한 장 줄 수 | 11pt 34줄, 10.5pt 36줄, 10pt 37줄 | |
| 한 줄 글자 수 | 11pt 약 70자 (한글 1, 영문·숫자 0.55, 8% 여유) | |
| 과제당 줄 수(프롬프트) | (11pt 한 장 줄 수 − 과제 수×2) ÷ 과제 수, 5~12줄 | 2 = 과제명 + 빈 줄 |
| 문장 길이 | 항목 40~100자(최대 2줄), 세부 20~70자(1줄) | 1번 작성본 |
| 날짜 | 진행·이슈·잘한점 항목 끝 `.(M/D)`, 계획은 예정일이 있을 때만 `.(~M/D)`, 배경은 없음 | |

글자 크기는 한 장에 들어가는 가장 큰 값(11 → 10.5 → 10pt)을 고른다. 10pt로도 넘치면 11pt로 되돌리고, 과제를 쪼개지 않고 과제 단위로 다음 장에 넘긴다. 이때 제목은 `1. 팀 (1/2)`, `1. 팀 (2/2)`가 된다.

## 5. 실행

```bash
python -m weekly_report team 조립자동보정팀 2026-W40          # 팀 이름
python -m weekly_report team P-ASM-001 2026-W40              # 과제 ID → 그 과제의 팀
python demo/team/run_team_demo.py                            # 예시 2개 다시 만들기
```
- 웹 테스트 화면: 「보고 자료 생성」 → **팀 주간보고 (요약 + 과제별, 선택 과제의 팀)**.
  응답이 없으면 프롬프트가 표시되고, AI 답을 붙여 넣으면 이어서 진행한다(기존 흐름과 같음).
- 작성자는 팀 첫 과제 담당자다. 업데이트 시간은 팀 과제 주간 정리본 중 가장 늦은 수정 시각이다.

## 6. 예시 (`demo/team/out/`)

| 파일 | 내용 |
|---|---|
| `팀주간보고_조립자동보정팀_2026-W40.pptx` | 요약 1장(P-ASM-001, 11pt) + 주간 장표 1장 |
| `팀주간보고_검증팀_2026-W39.pptx` | 합성 5과제 요약 1장(11pt, 26/34줄) + 주간 장표 5장 |
| `data/derived/summary/*/*.json`, `output/*/summary_check_*.txt` | 과제별 요약 JSON과 검증 보고서 |
| `preview/*.png` | LG스마트체 미리보기 |

- `demo/team/mock_responses/`의 응답 6개는 EXAONE이 아니라 Claude가 `prompts_sent/`의 프롬프트를 읽고 입력 근거만으로 쓴 것이다.
- 실제 EXAONE 응답 품질(문장 길이, 날짜 표기, 이슈·잘한점 구분)은 사내 환경에서 확인해야 한다.
- 처음 쓴 예시에는 입력에 없는 사이트 수("4개")가 있었고, 검증에서 `[오류] 입력에서 확인되지 않는 수치 4`로 잡혀 고쳤다.
