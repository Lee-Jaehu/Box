# Phase 2 — 계산 엔진 뼈대와 샘플 요청

- 작성일: 2026-10-25
- 상태: **뼈대 완료, 실제 샘플 대기.** 기관별 엑셀 열 이름과 알림 문구 패턴은 샘플을 받은 뒤 채움
- 코드: `notion-budget/budget/`, 테스트: `notion-budget/tests/` (`python -m unittest discover -s tests -v`)
- 테스트 데이터는 모두 테스트 안에서 만든 **가상 예시**입니다. 실제 기관 형식이 아닙니다

## 1. 구조

```
엑셀/CSV (월 1회, 숫자의 기준) ──▶ excel.parse_file ─┐
                                                     ├─▶ rules.classify ─▶ model.assign_keys ─▶ notion (거래 DB)
알림 원문 (노션 수신함) ──────────▶ alerts.parse ────┘          │
              └─ 미해석 보관 · FormatWatch(형식 변경 의심)      ▼
                                              reconcile: 잔액 연속성 · 알림 누락 · 카드 청구액 ─▶ notion (월별 대사)
```

## 2. Phase 1 결과를 어디에 반영했나

| Phase 1 근거 | 반영 |
|---|---|
| T09 알림 형식이 바뀌면 인식이 조용히 멈춤 | `alerts.parse`는 해석 실패도 결과로 돌려줌(수신함 '미해석'). `FormatWatch`가 같은 발신처의 돈 알림 해석 실패가 3번 연속이면 한 번 경고 |
| T17 알림 원천이 늦거나 빠짐 | 알림은 미리보기. `reconcile.alert_coverage`가 월말 엑셀과 맞춰 "알림 누락 n건"을 보고 |
| T02 연동 끊김 | 연결이 없는 구조(엑셀). 별도 코드 없음 |
| T03 같은 금액 두 건이 한 건으로 합쳐짐 | `model.assign_keys`가 같은 날·같은 곳·같은 금액을 등장 순서로 구분. 같은 파일 재입력은 같은 키라 중복 입력도 막음 |
| T05·T20 이체·카드대금·대출·저축을 어디에 적나 | `rules.classify`가 자산 이동으로 기본 분류하고 근거 문장을 남김. 사용자가 고친 값은 덮어쓰지 않음. `monthly_totals`는 자산 이동을 빼고 카드 취소는 지출에서 차감 |
| T07 숫자 불일치 | `reconcile.balance_breaks`(앞 잔액 + 금액 = 다음 잔액), `card_statement_diff`(이용내역 합계 vs 청구 총액) |
| T21 노션 템플릿 수식 오류 | 노션에는 숫자만 씀. relation·rollup·formula에 계산을 맡기지 않음(`notion.py`) |
| T19 조회·편집 | 노션 뷰로 해결. 거래 DB에 검색·필터용 속성(계정, 구분, 카테고리, 출처, 원본 위치)을 둠 |

## 3. 노션 DB (`notion.DATABASES`)

| DB | 주요 속성 |
|---|---|
| 거래 | 이름, 날짜, 금액(원, 지출 음수), 계정, 구분(지출·수입·내 계좌 이체·카드대금·대출 상환·저축), 카테고리, 출처, 분류 근거, 메모, 원본키, 원본 위치 |
| 알림 수신함 | 원문, 발신처, 받은 시각, 상태(미해석·해석됨·엑셀과 대사됨·형식 변경 의심), 원본키 |
| 월별 대사 | 월, 계정, 엑셀 기준 잔액, 계산 잔액, 차이, 잔액 끊김, 알림 누락, 청구액 차이 |
| 주간 인사이트 | 주, 내용, 근거 |

I3(보유자산·자산배분 알림)는 이 뼈대에 아직 넣지 않았습니다. 가드레일 5개(Phase 0 5-2절)를 지키는 별도 DB로 붙입니다.

## 4. 아직 없는 것

- 노션 API 호출부: 토큰 저장, 첫 실행 때 DB 자동 찾기·연결, 초당 3회 제한과 `Retry-After` 처리. 노션 integration 토큰을 받은 뒤 붙임
- 카드 청구 명세서(PDF) 해석: 샘플을 받은 뒤
- 암호가 걸린 엑셀: 지금은 "암호를 풀고 다시 저장해 주세요"라는 오류만 냄
- 카테고리 자동 분류: 지금은 모두 '미분류'. 가맹점 이름 규칙은 실제 거래를 본 뒤 만듦

## 6. 현대카드 명세서 구조 (2026-10-25, 앱 화면 캡처 기준)

사용자가 보낸 앱 화면 캡처로 확인한 **구조만** 적습니다. 금액·가맹점·계좌 등 개인 정보는 저장소에 남기지 않습니다(이 저장소는 공개).

| 항목 | 확인한 내용 | 설계 반영 |
|---|---|---|
| 결제일과 출금일 | 결제일이 휴일이면 다음 영업일 출금으로 표시 | 은행 출금(카드대금)과 명세서를 맞출 때 날짜 ±3일 허용 |
| **이용 기간** | 결제일 25일 기준 일시불·할부 이용 기간이 **전전월 14일~전월 13일**. 단기카드대출은 기간이 따로 있음 | 카드별 청구 주기 설정 필요. `card_statement_diff(start, end)`에 이 기간을 넣음 |
| 총 결제 금액 | **일시불 + 할부(원금 + 수수료)** 로 나뉘어 표시. 카드 상품이 여러 장이면 카드별 소계 | 대사는 카드별 소계와 총액 두 단계로 |
| 이용 내역 한 줄 | 가맹점, 이용일, 일시불/할부 구분, **청구할인 금액**(예: "0.8% 할인 -○원") | 한 카드에서 **이용 내역 22건 합계 = 명세서 일시불 금액**이 원 단위로 일치함을 확인. 즉 내역의 금액은 **할인 후 청구 금액**. 다른 카드는 캡처 해상도 때문에 ○원 차이를 판별하지 못함 → 엑셀로 확인 |
| 할부 | 이번 회차 청구액 + "무이자/유이자 할부(n/N)" + 원래 이용 금액 + 수수료 | 거래에 `이용금액`, `이번 회차`, `n/N`, `수수료` 필드 추가 필요. **지출 인식 기준 결정 필요(아래)** |
| 취소 | 이용 금액이 음수이고 청구 금액이 0원인 줄이 있음 | 취소를 별도 줄로 남기고 청구 0원 처리 |
| 유료 부가상품 | 할인 상품 이용료가 일시불 줄로 청구됨 | 카테고리 '금융 수수료'로 분류 규칙 추가 |
| 생활요금 자동결제 | 통신요금 자동결제가 별도 묶음으로 표시 | 고정지출 표시 후보 |
| 앞으로의 할부 | 다음 두 달 할부 납부 예정액 표시 | 월별 대사에 '다음 달 예정 청구액' 속성 후보 |
| 내려받기 | 앱에는 "이미지로 저장 / 이메일로 받기 / 인쇄"만 있고 엑셀은 없음 | Phase 0 조사와 같음. **홈페이지에서 엑셀**을 받아야 함 |

### 결정이 필요한 것: 할부의 지출 인식 기준
- (A) **이용일에 전액**을 지출로 잡음. 예산·소비 습관 관점. 노션의 월 지출이 카드 청구액과 달라지므로, 대사는 '청구 회차' 필드로 따로 맞춤
- (B) **청구 회차만** 매달 지출로 잡음. 현금 흐름 관점. 큰 물건을 산 달의 지출이 작게 보임
- 두 값을 모두 저장하고 화면 기본값만 고르는 것도 가능함

**결정 (2026-10-25): 둘 다 저장, 화면 기본값은 이용일 기준.** `Transaction.amount`는 이용일 전액이고, 명세서 값은 `billed`·`billing_month`·`installment`·`fee`에 둡니다. `rules.monthly_totals(basis="billed")`로 결제월 기준 합계도 냅니다. 회차 금액은 카드사마다 반올림이 달라 계산하지 않고 명세서 값을 그대로 씁니다.

**남은 과제:** 3개월 할부는 명세서 세 장에 같은 이용 건으로 나옵니다. 지금 구조에서는 1회차 청구만 담기고 2·3회차 청구를 담을 곳이 없습니다. 실제 명세서 엑셀을 본 뒤 '거래'(이용 건 1개)와 '청구'(명세서 줄, 회차마다 1개)를 나눠 원본키로 잇는 쪽으로 정합니다.

## 7. 신한카드 문자 알림 (2026-10-25, iPhone 문자 캡처 기준)

사용자 문자 캡처의 원문 10건(승인 9, 취소 1)으로 `alerts.PATTERNS["shinhan_card"]`를 만들었고 10건 모두 해석됐습니다. 원문은 저장소에 넣지 않았고, 테스트에는 같은 구조의 가상 문구만 넣었습니다.

| 항목 | 확인한 내용 | 반영 |
|---|---|---|
| 발신 번호 | 1544-7200 | `alerts.SENDERS`로 발신처 키(shinhan_card)에 연결. 모르는 번호는 숫자만 남겨 수신함에 미해석으로 둠 |
| 형식 | `[Web발신] 신한법인(카드 끝 4자리)승인 이름(가림) 금액원 MM/DD HH:MM 가맹점 잔액○원` | 연도는 받은 날짜로 보정(1월에 받은 12월 승인 처리) |
| 취소 | 같은 형식에 `취소`, **잔액 없음** | 양수(환불)로 기록 |
| 줄바꿈 | 휴대폰 화면에서 가맹점명이 두 줄로 나뉨. 금액이 첫 줄에 붙는 경우도 있음 | 가맹점명 안의 공백·줄바꿈은 지움 |
| **잔액** | 통장 잔액이 아니라 **카드의 남은 한도**. 연속된 승인에서 앞 한도 − 이번 금액 = 이번 한도가 정확히 맞음 | `reconcile.limit_gaps`: 이 등식이 깨지면 **알림 없이 쓴 금액**을 바로 보고(월말 엑셀 전 T17 탐지). 한도가 늘면(결제·취소 반영) 끊김으로 보지 않음. 캡처 10건에서는 끊김 없음 |
| 상품 | 이번 캡처는 **법인카드**(`신한법인`). 개인 신용·체크카드 형식은 원문 확인 전 | 패턴은 `신한법인/신한카드/신한체크`를 받지만, 개인 카드는 실제 원문으로 다시 확인해야 함 |
