- **투자자문업 (자본시장법 제6조 ⑦)**: "금융투자상품등의 가치 또는 금융투자상품등에 대한 투자판단(종류, 종목, 취득·처분, 취득·처분의 방법·수량·가격 및 시기 등에 대한 판단을 말한다)에 관하여 자문에 응하는 것을 **영업으로** 하는 것" ✅
  - [CaseNote 자본시장법 제6조](https://casenote.kr/%EB%B2%95%EB%A0%B9/%EC%9E%90%EB%B3%B8%EC%8B%9C%EC%9E%A5%EA%B3%BC_%EA%B8%88%EC%9C%B5%ED%88%AC%EC%9E%90%EC%97%85%EC%97%90_%EA%B4%80%ED%95%9C_%EB%B2%95%EB%A5%A0/%EC%A0%9C6%EC%A1%B0) · 원문: [국가법령정보센터 자본시장법](https://www.law.go.kr/법령/자본시장과금융투자업에관한법률)

  - [금융위 법령해석: 유사투자자문업자의 개별 조언](https://better.fsc.go.kr/fsc_new/replyCase/LawreqDetail.do?stNo=11&muNo=85&muGpNo=75&lawreqIdx=3505) · [아주경제(2024-07)](https://www.ajunews.com/view/20240722105618484) · [MBC](https://imnews.imbc.com/news/2024/econo/article/6619656_36452.html)

  - [CaseNote 2018도4413](https://casenote.kr/%EB%8C%80%EB%B2%95%EC%9B%90/2018%EB%8F%844413)

- **부동산**: 제6조 ⑦의 "금융투자상품등"은 시행령 제6조의2의 투자대상자산을 포함하고, 여기에 부동산과 부동산 관련 권리가 들어가는 것으로 알고 있으나 **이번에 조문을 확인하지 못함** ❓. 제7조 ③(불특정 다수 대상 간행물 등의 예외)도 원문 미확인 ❓

### 2-2. 해석 (작성자 판단)
- 핵심 요건은 **"영업으로"**입니다. **본인 혼자 쓰는 노션에서 본인 포트폴리오를 계산하는 기능**은 영업성이 없으므로 투자자문업에 해당할 가능성이 낮습니다.
- 위험해지는 경우는 이렇습니다.
  1. 템플릿을 **배포·판매**하면서 종목 추천 로직을 넣는 경우: 유사투자자문업 신고 대상이 되거나, 개별 맞춤 추천이면 투자자문업에 해당할 수 있습니다.
  2. **Phase 3 테스트 사용자 5명**에게 각자 보유자산에 맞춘 종목·매매 시점 추천을 보여주는 경우: "특정인 대상 투자판단 제공"에 가까워집니다. 대가가 없으면 "영업" 요건이 약해지지만, 회색지대입니다.
  3. 추천이 자동 매매나 주문으로 이어지는 경우: 투자일임업 쟁점이 생깁니다.
- 별개로, LLM 종목 추천은 품질 검증이 어렵고 "4주 뒤에도 쓰는 가계부"라는 목표와도 거리가 멉니다.

## 3. Notion API 제약과 "노션 = 화면, 계산 = 외부 Python" 구조

### 3-1. 확인된 제약 ✅
| 항목 | 내용 | 출처 |
|---|---|---|
| 호출 제한 | 연결(integration)당 **평균 초당 3회**, 순간 초과 일부 허용. 워크스페이스 단위의 공유 한도도 별도로 있고 요금제에 따라 다름. 초과 시 HTTP 429와 `Retry-After` 헤더 | [Request limits](https://developers.notion.com/reference/request-limits) |
| 크기 제한 | rich text 2,000자, 요청당 relation 100개, 요청당 블록 1,000개, 페이로드 500KB | 동일 |
| API 버전 | **2025-09-03부터 database와 data source가 분리됨** (하위 호환 아님). 조회는 `POST /v1/data_sources/{id}/query`, 페이지 생성 parent도 data source ID로 지정 | [Upgrade guide](https://developers.notion.com/guides/get-started/upgrade-guide-2025-09-03) |
| relation·rollup·formula를 API로 읽을 때 | 페이지 응답에서 relation은 **25개까지만** 반환(`has_more`). **relation 참조가 25개를 넘으면 그 relation에 의존하는 formula는 25개만 계산됨.** 다단계 relation의 rollup·formula는 "올바르지 않을 수 있음" | [Page property values](https://developers.notion.com/reference/page-property-values) · [Retrieve a page property](https://developers.notion.com/reference/retrieve-a-page-property) |
| rollup 기능 | rollup당 계산 1개, rollup의 rollup 불가, 교차집계 불가 ⚠️ | [sync2sheets(2026)](https://sync2sheets.com/blog/notion-rollups/) |

### 3-2. 판단: **이 구조가 맞습니다. 단, 아래 조건을 붙입니다.**
1. **정본(source of truth)은 Python 쪽에 둡니다.** "월별 요약" DB의 월 거래는 한 달에 수백 건입니다. 따라서 25개 제한에 걸리는 relation 기반 rollup·formula 값을 **API로 읽어 계산에 쓰면 안 됩니다.** 월 합계, 대사, 예측, 인사이트는 Python에서 계산하고 Notion에는 **숫자 속성으로 기록**합니다.
2. Notion 화면의 rollup은 **보기 편의용**으로만 남길 수 있습니다. 앱 화면 계산은 25개 제한과 무관할 것으로 보이지만 ❓, Python이 쓴 값과 rollup 값이 다르면 대사 화면에 경고를 띄우는 식으로 교차 점검에 활용합니다.
3. 행 단위의 단순 수식(부호 처리, 월 키, 표시 문구)만 Notion formula로 처리합니다.
4. 처리량: 월 300건이면 쓰기 300회, 초당 3회로 약 2분입니다. 12개월 백필(약 3,600건)도 약 20분이므로 호출 제한은 병목이 아닙니다. 업서트(중복 방지) 키 설계가 더 중요합니다.

### 3-3. Phase 3 계획과 충돌하는 지점
- 원래 계획은 "GitHub Actions 등으로 정기 동기화"입니다. 하지만 1절에서 권고한 **D(엑셀)는 사람이 로그인해서 내려받는 방식**이라, Actions가 은행에서 파일을 직접 가져올 수 없습니다. 그래서 **파일을 Python에 넘기는 경로**를 정해야 합니다(결정 질문 3).
- 거래 데이터와 원본 파일은 **Git 저장소에 커밋하지 않습니다**(.gitignore 처리). 저장소 공개 여부와 무관하게 적용합니다.

## 4. 다음 Phase를 막는 환경 문제 (사전 고지)

1. **네트워크**: 현재 세션은 law.go.kr를 포함한 외부 호스트에 직접 접속할 수 없습니다. Phase 1의 리뷰 수집(`play.google.com`, `itunes.apple.com` RSS, `www.googleapis.com` YouTube Data API, `openapi.naver.com`)도 같은 이유로 막힐 것입니다. 환경 설정의 Network access에서 해당 도메인을 Allowed domains에 추가하거나 접근 수준을 넓혀야 합니다([안내](https://code.claude.com/docs/en/cloud-environments#network-access)).
2. **API 키**: YouTube Data API 키와 네이버 검색 API Client ID/Secret을 환경 시크릿으로 넣어야 합니다.
3. **Codex**: 이 환경에는 Codex 도구가 없습니다. Phase 1의 독립 재분류(kappa 측정)와 Phase 3의 코드 리뷰에 쓰려면 OpenAI API 키를 시크릿으로 받아 API로 호출하는 방법이 있습니다. 대안이 필요하면 결정 질문 7에서 정해 주세요.
